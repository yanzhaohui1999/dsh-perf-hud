## 布局

### 标签不收缩、数值换行

- **标签不收缩、数值换行**:行布局是 `label { flex: 0 0 auto; nowrap }` + `value { flex: 1 1 auto; textAlign: right }`;反过来会把标签挤成"一字一行"(实测「宿主事件到达」竖排过)。

### 长文本用块式 + 主动断行

- **长文本用块式 + 主动断行**:可能超一行的行(概览、折叠摘要)用"标签独占一行 + 值左对齐 + `white-space: pre-line` 自己给 `\n`",不要赌浏览器宽度(曾断在 `最多` 后面,把 `ChatView 22×` 甩到下一行)。

### 标题栏是一行永不换行的工具条

- **标题栏是**一行永不换行**的工具条:显式左右两组,只有文字可以让位**。`S.head` 不带 `flexWrap`,分 `headLeft`(可压缩:`minWidth: 0` + `overflow: hidden`,里面是标题 / 返回键 / 场景标签 / fps)与 `headRight`(控件,`flex: 0 0 auto`:设置 / 收起 / 关闭)。来历是一次真事故:工具条里每个元素都是 `flex: 0 0 auto`(上面「标签不收缩」那条本来是给**数据行**写的),总宽一超,浏览器就按 DOM 顺序把**尾部三个控件整组**丢到第二行、还左对齐 —— 看着像下面那一块的动作按钮;主界面一行放得下、卡顿详情放不下,于是"两个头部的按钮位置关系不一样"。分组也**不许**再用某个元素上的 `margin-left: auto`(那个技巧只在它所在的那一行生效,一换行就散)。三条实测出来的硬性:① 文字优先级是**标题 > 场景标签 > 其余**,场景用 `flex: 0 100 auto` 先让位(「空闲…」还读得出要紧的那个词,「开发者详…」等于没写);② **亚像素收缩就足以触发省略号** —— zh 详情页原来只差 0.17px,所以头部间距用 6、头部按钮 `padding: 2px 6px`(`S.headBtn`,只作用于这一行);③ **新增头部控件前先量**:头部预算现在是 4 个控件 + 标题 / 场景 / `←`,「深录」因此从标题栏移到了开发者详情的标签页行(它是唯一"只在某一屏出现"的头部控件,却占着最挤那一行 —— 实测把该屏标题挤到 21px)。`← 返回` 缩成 `←`(悬停给全文)也是这笔账的结果。

## 文案

### 能不说就不说

- **能不说就不说**:「最多」与「最差那条」名字相同时整行不显示(它只是把同一句话说两遍);说明文字放 `title` 悬停,不占正文。概览两行同理:`overviewLine1()` **已删掉 `(最差那条:未归因)` 后缀** —— 它与紧接着的 `overviewLine2()` 里 `最差那条:<归属>` 的**触发条件完全相同**(都是 `primaryBlame(worst) === null`),相邻两行必然把同一句话说两遍;现在第一行只给 `帧 Xms · LT Yms · 命中 a/b`,「最差那条是谁」只由第二行给,两个口径本该分开读的提醒由第二行自己的标签承担(断言:第一行不含 `未归因`、第二行含)。「最差事件」块同理:`eventValueText(row)` 一行说清三种状态(未开录 → `未开录`;没有事故 → `还没抓到(≥100ms)` —— 阈值写在这一行里,不再另起一行重复;有事故 → `严重/警告 326ms`),`watchFlagText()` 只在"读回 / 裁掉 / 落盘失败"这类**还有话要说**时才返回第二行,未开录与"还没抓到"都不重复。两个一次性说明(`state.copyNote` / `state.pickNote`)由 `resetLayout()` 一并清掉 —— 布局都回到默认了还挂着旧说明,只会让人以为又出错了。

### 长度预算

- **长度预算**:概览两行与**六个**折叠组摘要都有字符上限(36 / 60 / **26** / 30 / 34 / 24 / **40** / **30**,顺序 = 概览两行 + 取证明细 / DOM 与堆 / 宿主与链路 / 工具箱 / **包 × 来源** / **技术细节**),由 `tests/logic.mjs` 钉住 —— 本会话看不到浏览器渲染,只能靠预算把"又挤成三行"这类回归钉在测试里。改文案必须重跑。**这份清单以断言为准**:AGENTS §5 原来抄过这份清单,曾写成 34(记的是另一组数字),现在那边只留"以断言为准"这一句 —— 对不上时改文档,不要改断言。第五组「包 × 来源 · 窗口」的摘要(`crossSummary`)从"没有预算"补上了 —— 它的名字与来源都可能很长(`dsh-client-ui-renderer · DOMWebSocket.onmessage 1234ms` 实测 **53** 字符,在 396px 里会折行),现在用 `clipName()` 把两个名字各自截到 `CROSS_SUMMARY_NAME_MAX` / `CROSS_SUMMARY_SRC_MAX`(14 / 15,完整名字在展开后的交叉表里)。补预算时要拿**真实量级**的名字(见 [死路](dead-ends.md) 第 13 条)。

### i18n 词典成对改

- **i18n 词典成对改**:`DICT.zh` 与 `DICT.en` 同时加键(现在中英各 **421** 键)—— 两条断言钉住这件事(logic.mjs):**键集合必须一致**、**每个键都得有人引用**(撤下界面时留下的死键会被报出来;死键那条只认字面量 `t('…')` / `translate('…')`,真要加动态取键得先放宽它)。**兜底策略跟文档语言**:locale 服务不在时按 `document.documentElement.lang`(取不到退 `navigator.language`)选那本字典,不是中文就用英文 —— 写死中文会让英文用户看到中文,简单反转(`DICT.en ?? key`)又会让中文用户看到英文,两种都错。

## 交互

### 可点 / 不可点的界线

- **可点 / 不可点的界线(不要做假按钮)**:可点 = 「按来源 / 按包」小表的**具名行**(→ `copyText` 复制「名字 + 毫秒」,成功/失败都照实写进 `state.copyNote`)、工具箱事故清单行(→ 选中)、帧条**有 LoAF 的格子**(→ 钉住那一帧)、组头(→ 折叠)、**可疑脚本的每一行**(→ 复制那条证据行);**不可点** = 堆叠条的**色段**本身(`cursor` 是 `default`)、「其余」那一行(它是合计数,没有单个名字可复制)。

### 按钮按需出现

- **按钮按需出现,不留"点了没反应"的动作**:「全部折叠」只在**有组开着**时渲染(`anyGroupOpen()`),「恢复默认布局」只在 `layoutDirty()` 为真时渲染(有组开着 / 翻帧被钉住 / 手选了事故 / `scope` 不是 `worst` / 挂着一次性说明);两者都无意义时整行不渲染。新加"布局类"按钮前先问:默认状态下点它会发生什么?什么都不会发生就别显示。

## 尺寸与让位(2026-10-18,真页面实测)

### 高度:内容撑到 82vh 就滚,而且滚的是正文

- 展开态只有一条尺寸规则:`{ width: PANEL_WIDTH, maxHeight: '82vh' }` —— **没有 height**,高度就是内容高度。
- 卡顿详情里把「技术细节」展开之后必然超过一屏(环 + 本帧/窗口两套脚本拆解 + 重叠的 long task + 可疑脚本 + 交叉表 + 口径段),所以一定会滚;面板又是 `position: fixed; bottom: 12`,变高是**向上长**。
- 滚动容器是**正文**(`S.scroll`),不是根节点:根节点是 flex 列 + `overflow: hidden`。以前 `overflowY: auto` 挂在根节点上,滚轮滚走的是整块 —— 标题栏连同「收起 / 关闭」一起滚没了(1400×757 的卡顿详情里必然发生)。

### 宽度:一个来源,而且随视口收

- 桌面宽度是 `PANEL_WIDTH = 396`,但真宽度由 `panelWidthFor(innerWidth)` 算:**`min(396, 视口 − 24)`,下限 240**。来历是手机:`393px` 视口下定宽 396 会直接溢出去(实测 `left = −15`、`right = 381`)——「性能 HUD · 已关」被切成「能 HUD · 已关」,药丸那条横贯整屏、标题被挤成「生…」。
- 收起态与已关态**不设宽度**(内容多宽就多宽,只封顶):已关是一枚 168px 的小 chip,不该跟着展开态撑成一条。
- 药丸在**窄屏(< 480px)转紧凑档**,只丢「检测 N 次」这一格(明细本来就在悬停与设置页里);fps / 最差帧 / 最差 longtask 三个基本读数一个不丢(§5「折叠不是看不见」)。判据只有视口宽度:面板样式全是内联的,没有媒体查询可用。
- 宽屏下药丸仍可能比展开态宽(实测 1400×757 的 zh:425px vs 396),那是**一行不可换行的读数**撑的,不是写错;钉死 396 会在英文下截断(`worst frame 28ms` / `detected 1551 times`),所以宽屏只给下限。

### 审批卡让位(不许挡住批准按钮)

- 审批面板是 **composer takeover**:「拒绝 / 允许一次」两个真按钮在卡片右下角(`actionRow` 是 `justify-content: flex-end`),正压在 HUD 停的那一列上 —— 这就是"面板挡住批准按钮"。
- 稳定钩子是外壳给的 `data-approval-key`(见 `@deepseek-ai/dsh-client-ui-approval` 的 `ApprovalPanel`);它的类名是构建期哈希(`mna1RW_*`),不能用。
- 判定是纯函数 `hudDodge`(client.model.js),渲染层只量一次 rect:卡片右边界伸进我们这一列 → 抬到卡片上方(`bottom = 视口高 − 卡片顶 + 12`),并把 `maxHeight` 收到抬上去之后剩下的空间(不跟着收就会被顶出屏幕上沿);上方不足 200px 则退到左下角(动作按钮右对齐,挡不到);卡片占满整屏 / 不可见 / 还在视口下方 → 一律不动。
- 真页面那一侧由 `tools/check-panel.mjs` 验:插一张假 `[data-approval-key]` 卡,断言面板让开;拿掉之后回到右下角。

## 渲染性能

### 折叠组默认不做昂贵分析

- **折叠组默认不做昂贵分析,现在由 `group()` 的 thunk 保证**:`group(key, label, summary, ...children)` 支持"唯一一个 child 且是个函数"的形式,折叠时**连函数体都不进**;六个调用点(`detail` / `cross` / `dom` / `host` / `tools` / `tech`)全传 thunk,所以「取证明细」与「技术细节」收起时脚本按包 / 交叉表 / 帧条一次都不算。代价要记住:**`cross` 嵌在「取证明细」的 thunk 里,「技术细节」又嵌着「取证明细」那条链上的同一批块** —— 一展开任一层,调用方就先构造 `crossTable(scriptPkgTally())` 与 `kids` 数组(4×5 格,代价低),所以窗口聚合那份缓存不能省。摘要那一行(`techSummary`)即使收起也会被求值,所以它**只读已经算好的 `detail`**,不重新采、不重新解析。
